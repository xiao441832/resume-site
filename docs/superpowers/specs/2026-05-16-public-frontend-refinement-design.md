# 前台页面二次精修设计说明

## 一、目标

本次优化聚焦公开前台页面，包括首页和个人公开简历详情页。目标是把现有蓝白风格继续打磨为清爽、现代、适合毕业设计展示的 SaaS 风格界面，解决当前页面内容显得偏空、卡片秩序不够强、模块层次不够丰富的问题。

本次不重构后端，不修改数据库字段，不改变搜索、查看简历、留言提交、后台编辑后展示等原有业务逻辑。

## 二、视觉方向

整体使用蓝白简洁风格：

- 主色继续使用科技蓝，页面底色使用浅灰或浅蓝灰。
- 内容区域以白色卡片、浅边框、浅阴影组织信息。
- 圆角保持克制，卡片和按钮以 8px 到 12px 为主。
- 标题层级、正文大小、按钮样式保持统一。
- 页面保留足够留白，但通过特性卡片、结构化区块和统一卡片高度减少空旷感。
- 不使用夸张动画、轮播图、假统计数字、深色大背景或花哨装饰。

## 三、首页设计

### 顶部导航

首页顶部导航保持轻量：

- 左侧显示系统名称。
- 右侧显示“公开简历”“登录”“注册”等入口。
- 当前页面入口可使用轻微蓝色高亮。
- 移动端保持单行或折行不拥挤，不出现按钮溢出。

### Banner 区域

首页 Banner 仍保持左侧标题介绍、右侧搜索框：

- Banner 背景使用浅蓝渐变或浅色块。
- 左侧标题突出系统定位，描述文字增强可读性。
- 右侧搜索框做成白色搜索卡片，包含标题、输入框、搜索按钮。
- 搜索表单仍使用原有 `GET` 请求和 `q` 参数，不影响搜索功能。
- Banner 下增加三个简短平台特性：多用户、公开展示、安全可靠。
- 特性只说明系统能力，不写假数据。

### 公开简历卡片

首页公开简历卡片是本次重点：

- 桌面端三列，平板两列，手机一列。
- 每张卡片高度统一，按钮固定在卡片底部。
- 上传头像和首字头像使用统一尺寸、圆角和视觉样式。
- 姓名、岗位、城市、简介和查看按钮布局统一。
- 简介最多显示四行，超出后省略。
- 卡片增加轻微 hover 上浮和阴影变化。
- 不改变“查看简历”的跳转地址和 `username` 逻辑。

### 首页空状态

当没有公开简历时，不再只显示普通文字，而是显示白色空状态卡片：

> 暂无公开简历，用户公开发布后将在这里展示。

该空状态不写假用户、不写假简历。

## 四、个人公开简历详情页设计

### 顶部导航

详情页导航与首页保持一致：

- 左侧显示系统名称。
- 右侧保留“首页”“公开简历”“登录”“注册”等入口。
- 页面内锚点导航保留技能、经历、项目、教育、联系入口。
- 移动端使用 Bootstrap 折叠菜单，避免错位。

### 首屏区域

详情页首屏继续保持左侧个人介绍、右侧个人信息卡片：

- 左侧展示求职状态、姓名、职业标题、个人简介和操作按钮。
- 操作按钮统一样式，包括发送邮件、留言、返回首页或下载简历。
- 右侧个人信息卡片增加圆角、浅阴影、顶部蓝色装饰线。
- 右侧卡片在桌面端使用 sticky 效果，移动端正常上下排列。
- 联系方式列表使用固定标签宽度和可换行内容，GitHub、网站链接允许自动换行。
- 不修改真实联系方式字段和 Jinja2 模板变量。

## 五、详情页内容模块

详情页包含专业技能、工作经历、项目作品、教育背景、证书荣誉和联系我。

优化规则：

- 有内容的模块使用白色卡片或结构化区块展示。
- 模块标题可配合克制的 Bootstrap Icons 图标。
- 没有内容的模块避免半成品感。
- 如果模板逻辑清晰，空模块可以显示统一空状态卡片。
- 空状态文案统一为“该模块暂未填写，完善后将在此展示。”
- 不硬编码假数据。
- 不修改数据库字段。
- 不影响后台编辑后在前台正常展示。

## 六、联系我区域

联系我区域改为白色卡片布局：

- 左侧展示邮箱、电话等联系信息。
- 右侧展示留言表单。
- 表单输入框、文本域、提交按钮使用统一样式。
- 保留 `form.hidden_tag()`、原有表单字段、提交地址和 CSRF 逻辑。
- 不影响留言提交功能。
- 检查浏览器控制台，不应出现明显 JavaScript 报错。

## 七、响应式要求

必须兼容电脑端、平板端和手机端：

- 首页公开简历：电脑三列，平板两列，手机一列。
- 详情页首屏：电脑左右布局，手机上下布局。
- 搜索框、按钮、头像、卡片和联系信息不能溢出。
- 页面不能出现整体横向滚动条。
- 表单和按钮在小屏幕上可自然换行或撑满宽度。

## 八、实现边界

优先修改：

- `app/templates/public/index.html`
- `app/templates/public/resume.html`
- `app/static/css/main.css`
- `tests/test_frontend_polish.py`

本次原则上不修改后端 Python 代码。如果实现过程中发现必须改后端，需要先说明原因，再决定是否调整。

CSS 继续使用统一变量，例如：

- `--brand`
- `--brand-soft`
- `--ink`
- `--muted`
- `--line`
- `--soft`
- `--paper`

不删除已有 class，除非确认没有其他页面依赖。新增 class 以 `public-`、`resume-`、`contact-`、`empty-` 等可读前缀为主。

## 九、测试与验收

代码层面需要补充或更新测试，覆盖：

- 首页存在优化后的 Banner、搜索卡片、平台特性和公开简历卡片结构。
- 首页空状态使用美观卡片。
- 详情页存在首屏、右侧信息卡、内容模块卡片和联系卡片结构。
- 关键图标和响应式类名存在。
- 原有搜索、查看简历、留言表单相关测试继续通过。

浏览器验收需要检查：

- 桌面宽度下首页公开简历三列展示。
- 手机宽度下首页简历卡片一列展示。
- 详情页桌面左右布局、手机上下布局正常。
- 没有整体横向滚动条。
- 按钮文字和链接不溢出。
- 控制台没有明显 JavaScript 报错。

## 十、自查结论

本规格只聚焦前台首页和个人公开简历详情页的视觉与结构精修。它不引入新数据库字段，不改变用户权限，不改变后台管理逻辑，不写假数据。实现完成后，页面应比当前版本更饱满、更统一，并保持蓝白简洁、现代 SaaS 风格。
