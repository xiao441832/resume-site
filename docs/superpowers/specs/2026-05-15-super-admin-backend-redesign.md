# 超级管理员后台体验重构设计说明

## 一、问题背景

当前系统已经具备超级管理员能力，包括全站统计、用户管理、账号封禁、禁止发布、封禁公开简历、留言管理和站点设置。但是超级管理员后台仍然复用了普通用户后台的整体菜单结构，侧边栏中直接显示“个人信息、技能、工作/实习经历、项目经历、教育经历、证书”等简历维护入口。

这种结构会让超级管理员后台看起来像“个人简历后台加了用户管理”，不像一个网站平台后台。毕业设计展示时，老师或评审更容易认为系统仍然偏个人站点，而不是完整的多用户管理系统。

本次优化目标是把 `/admin` 改造成平台管理后台，把 `/dashboard` 保持为普通用户简历后台，让两类后台在信息架构、页面文案和操作重点上明显区分。

## 二、设计目标

本次重构目标：

- 超级管理员后台主菜单体现“平台管理”，不再直接显示普通用户简历编辑菜单。
- 超级管理员控制台展示全站运营状态，而不是个人简历统计。
- 用户管理页面更像后台账号管理模块，能快速筛选异常账号和处理用户状态。
- 简历内容管理从“超级管理员自己编辑简历”改为“查看和管控用户内容”。
- 普通用户后台继续保留个人简历维护功能，不影响普通用户现有使用流程。
- 不引入 Vue、React、前后端分离，不大改数据库。

## 三、后台信息架构

超级管理员后台侧边栏改为：

```text
控制台
用户管理
简历管理
留言管理
站点设置
```

第一版不新增复杂的“操作日志”数据库表，避免扩大范围。页面上可以先预留最近操作说明，但不做独立日志存储。

普通用户后台侧边栏保持：

```text
仪表盘
个人信息
技能
工作 / 实习经历
项目经历
教育经历
证书
留言管理
```

这样超级管理员看到的是网站系统管理入口，普通用户看到的是个人简历维护入口。

## 四、超级管理员控制台设计

超级管理员 `/admin` 页面定位为“系统控制台”。

页面内容包括：

- 顶部标题：系统控制台
- 副标题：显示当前登录账号身份和后台用途
- 统计卡片：
  - 用户总数
  - 正常用户
  - 已封号用户
  - 公开简历
  - 封禁简历
  - 留言总数
  - 未读留言
- 快捷操作：
  - 查看用户管理
  - 查看简历管理
  - 查看留言管理
  - 查看前台首页
- 最近注册用户：
  - 用户名
  - 昵称
  - 邮箱
  - 账号状态
  - 发布权限
  - 注册时间
- 最近留言：
  - 留言人
  - 目标用户
  - 邮箱
  - 状态
  - 时间

控制台不展示普通用户自己的技能、项目、证书数量，避免角色混淆。

## 五、用户管理设计

`/admin/users` 保持为超级管理员用户管理入口，但页面增强为后台账号管理列表。

列表筛选项：

- 关键词：用户名、邮箱、昵称
- 状态：
  - 全部
  - 正常账号
  - 已封号
  - 禁止发布
  - 简历封禁

列表字段：

- 用户
- 邮箱
- 账号状态
- 发布权限
- 公开简历状态
- 简历内容数量
- 留言数量
- 注册时间
- 最近登录
- 操作

用户详情页改名为“账号档案”，内容分为：

- 账号概况：用户名、昵称、邮箱、注册时间、最近登录
- 状态卡片：账号状态、发布权限、公开简历状态
- 简历数据概览：技能、经历、项目、教育、证书、留言数量
- 管控操作：
  - 封禁 / 解封账号
  - 禁止 / 恢复发布
  - 封禁 / 恢复公开简历
- 最近留言

用户详情页可以提供“查看公开简历”按钮，如果该用户当前公开状态满足展示条件，则跳转 `/u/<username>`。

## 六、简历管理设计

新增或改造 `/admin/resumes` 页面作为“简历管理”入口。

这个页面不是让超级管理员编辑自己的简历，而是展示所有普通用户的简历发布状态：

- 用户
- 简历姓名
- 职业标题
- 城市
- 账号状态
- 发布权限
- 用户自己是否开启前台展示
- 是否被系统封禁
- 更新时间
- 操作

支持筛选：

- 全部
- 正在公开
- 用户隐藏
- 禁止发布
- 系统封禁
- 账号封禁

操作：

- 查看用户档案
- 查看公开简历
- 封禁公开简历
- 恢复公开简历

这样超级管理员可以从“简历视角”管理内容，而不是进入普通用户的 CRUD 菜单。

## 七、留言管理设计

`/admin/messages` 继续保留全站留言管理功能，但页面文案和信息更像平台后台：

- 留言人
- 目标用户
- 邮箱
- 电话
- 状态
- 提交时间
- 操作

后端查询需要关联 `users`，让超级管理员能看出留言发给哪个用户。

留言详情页继续支持：

- 查看留言内容
- 修改状态
- 填写处理备注
- 删除留言

普通用户 `/dashboard/messages` 不显示目标用户列，因为普通用户只能看到发给自己的留言。

## 八、站点设置设计

`/admin/settings` 保持为超级管理员专属页面，页面标题改为“站点设置”。

配置项继续包括：

- 站点标题
- SEO 描述
- 备案信息
- 是否开启留言

第一版不新增复杂配置项，避免让后台变得臃肿。

## 九、路由调整

超级管理员路由：

```text
/admin                    系统控制台
/admin/users              用户管理
/admin/users/<id>         账号档案
/admin/resumes            简历管理
/admin/messages           全站留言管理
/admin/settings           站点设置
```

普通用户路由保持：

```text
/dashboard
/dashboard/profile
/dashboard/skills
/dashboard/experiences
/dashboard/projects
/dashboard/education
/dashboard/certificates
/dashboard/messages
```

超级管理员访问 `/admin/skills`、`/admin/projects` 等旧资源入口时，第一版可以返回 404 或跳转到 `/admin/resumes`。推荐返回 404，减少混乱入口。

## 十、模板结构调整

当前 `admin/layout.html` 同时服务超级管理员和普通用户后台。可以继续复用模板文件，但菜单需要根据区域分开生成：

- `area == 'admin'`：显示平台管理菜单
- `area == 'dashboard'`：显示简历维护菜单

后续如果模板继续膨胀，可以再拆为：

```text
admin/platform_layout.html
admin/dashboard_layout.html
```

第一版先保持一个布局模板，降低改动风险。

## 十一、视觉风格方向

后台视觉风格应偏管理系统：

- 更清晰的页面标题和副标题
- 更明确的状态标签
- 表格字段更完整
- 统计卡片聚焦平台指标
- 操作按钮按后台动作命名，例如“查看档案”“封禁简历”“恢复发布”
- 减少个人站点感，避免把“个人信息、技能、证书”直接暴露给超级管理员主菜单

不做营销式大图和装饰背景，保持简洁、规整、便于老师看出系统管理能力。

## 十二、测试策略

需要补充或调整测试：

- 超级管理员侧边栏包含“控制台、用户管理、简历管理、留言管理、站点设置”。
- 超级管理员侧边栏不包含“个人信息、技能、工作/实习经历、项目经历、教育经历、证书”。
- 普通用户侧边栏仍包含个人简历维护菜单。
- `/admin` 显示系统控制台和平台统计。
- `/admin/users` 列表显示账号状态、发布权限、公开简历状态、简历内容数量和留言数量。
- `/admin/resumes` 可以按公开状态展示所有用户简历。
- 超级管理员可以从简历管理封禁和恢复公开简历。
- `/admin/messages` 显示目标用户信息。
- 普通用户不能访问 `/admin/resumes`。
- 全量测试和线上真实流程验证通过。

## 十三、部署影响

本次优化主要是后台页面、路由和查询逻辑调整，不需要新增数据库表。可以直接部署代码并重启 Gunicorn。

如果实现中需要让列表查询更高效，可以增加索引，但第一版暂不要求数据库迁移。

部署后需要验证：

- 超级管理员登录后进入系统控制台。
- 超级管理员主菜单不再显示普通用户简历维护入口。
- 用户管理、简历管理、留言管理、站点设置均可打开。
- 普通用户后台不受影响，仍能维护自己的简历。
- 公开简历展示和留言提交不受影响。
